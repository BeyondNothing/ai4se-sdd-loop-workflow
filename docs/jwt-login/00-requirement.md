# 需求：用户 JWT 登录认证

## 背景

系统目前缺少统一的用户身份认证能力。需要新增基于 JWT（JSON Web Token）的登录认证模块，使客户端在用户名密码校验通过后获得访问令牌，并在后续请求中携带令牌访问受保护资源。

## 目标

实现一套可落地的 JWT 登录能力，覆盖**登录页面 + 后端 API + 端到端联调**，包括登录签发、令牌校验、受保护资源访问，以及基础的登出/失效约定。

## 功能需求

### 1. 用户登录（API）

- 提供 `POST /api/auth/login` 接口
- 请求体：`{ "username": string, "password": string }`
- 校验用户名与密码；校验失败返回 `401`，成功返回：
  - `access_token`：访问令牌（JWT）
  - `token_type`：固定为 `Bearer`
  - `expires_in`：过期秒数
- 密码不得以明文存储；至少使用单向哈希（如 bcrypt）

### 2. JWT 令牌约定

- 算法：`HS256`（可配置密钥）
- Payload 至少包含：
  - `sub`：用户唯一标识
  - `username`：用户名
  - `iat`：签发时间
  - `exp`：过期时间
- Access Token 默认有效期：2 小时（可通过配置调整）
- 密钥通过环境变量或配置文件注入，禁止硬编码进仓库

### 3. 受保护资源访问

- 提供示例受保护接口，例如 `GET /api/auth/me`
- 客户端在请求头携带：`Authorization: Bearer <access_token>`
- 校验通过：返回当前用户基本信息
- 令牌缺失、格式错误、签名无效或已过期：返回 `401`

### 4. 登出（约定）

- 提供 `POST /api/auth/logout`
- 由于 JWT 无状态，服务端至少完成：
  - 校验当前令牌有效
  - 返回登出成功响应
- 可选增强（非必须，可作为扩展）：维护短期黑名单或令牌版本号使已登出令牌立即失效

### 5. 基础用户数据

- 至少支持本地用户存储（内存、文件或数据库任选其一即可）
- 预置或可初始化至少 1 个测试用户，便于联调与验收
- 本期不要求完整用户注册、找回密码、第三方 OAuth

### 6. 登录页面（Web UI）

- 提供可访问的**登录页面**（如 `/login`），包含用户名、密码输入与提交
- 页面通过调用 `POST /api/auth/login` 完成认证；成功后保存令牌（如 `localStorage` 或 Cookie，须在实现中说明）
- 登录成功后进入**受保护页面或区域**（如 `/` 或 `/home`），展示当前用户信息（调用 `GET /api/auth/me`）
- 提供**登出入口**，调用 `POST /api/auth/logout` 并清除本地令牌，回到登录页
- 错误密码时在页面上展示统一错误提示（不泄露用户是否存在）
- 未登录访问受保护页面时，应引导至登录页或拒绝访问

## 非功能需求

- **安全**：密码哈希存储；JWT 密钥可配置；错误信息不泄露密码是否存在等敏感细节（统一提示“用户名或密码错误”）
- **可配置**：密钥、过期时间、监听端口等可通过环境变量配置
- **可测试**：
  - 提供单元测试或接口测试，覆盖登录成功/失败、受保护接口鉴权成功/失败、过期令牌场景
  - 提供**端到端（E2E）验证**：在浏览器中完成「打开登录页 → 输入账号密码 → 登录成功 → 查看用户信息 → 登出」全流程（可用 Playwright MCP 或等价 E2E 方式）
- **可运行**：提供清晰的本地启动方式，依赖明确；启动后可通过浏览器访问登录页

## 验收标准

### API

1. 使用正确用户名密码调用登录接口，返回有效 JWT
2. 使用错误密码登录，返回 `401`，且不返回令牌
3. 携带有效 JWT 访问 `/api/auth/me`，返回对应用户信息
4. 不带令牌、带非法令牌、带过期令牌访问受保护接口，均返回 `401`
5. JWT payload 含 `sub`、`username`、`iat`、`exp`，且 `exp` 符合配置的有效期
6. 密码不以明文出现在存储与日志中

### 登录页面 / 端到端

7. 浏览器打开登录页，使用预置测试账号登录成功，并进入受保护页面/区域
8. 登录后页面能展示当前用户基本信息（与 `/api/auth/me` 一致）
9. 错误密码登录时，页面显示错误提示且不进入受保护区域
10. 登出后无法继续访问受保护页面/接口（需重新登录）
11. 相关自动化测试通过（含 API 测试；E2E 可按实现选用浏览器自动化）

## 范围说明

### 本次包含

- 登录签发 JWT
- 请求鉴权中间件/过滤器
- 受保护接口示例
- 基础登出约定
- **登录页面与受保护页面（最小可用 Web UI）**
- **浏览器端到端登录流程验收**
- 配置项与测试

### 本次不包含

- 用户注册 / 邮箱验证 / 找回密码
- Refresh Token 刷新机制（可作为后续迭代）
- RBAC 细粒度权限、多租户
- 复杂前端工程（多页 SPA 框架、设计系统）；本期仅需满足登录/展示/登出的最小页面
