# 需求：产品列表与目录导航（TOC）

## 背景

系统需要向用户展示可浏览的产品目录。当前缺少统一的产品列表页与**目录导航（Table of Contents，TOC）**能力，用户难以按分类/章节快速定位产品，也无法通过 API 获取结构化产品数据。

## 目标

实现**产品列表 API + 列表页 Web UI + TOC 导航**，使用户可以：

1. 通过 API 分页查询产品列表
2. 在浏览器中打开产品列表页，通过 TOC 快速跳转到各分类/区块
3. 完成端到端验收（页面加载、TOC 跳转、列表展示）

## 功能需求

### 1. 产品数据模型（最小字段）

每个产品至少包含：

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | string | 唯一标识 |
| `name` | string | 产品名称 |
| `category` | string | 所属分类（用于 TOC 分组） |
| `price` | number | 价格（展示用，单位元，保留 2 位小数） |
| `description` | string | 简短描述（可选，列表页可截断展示） |
| `status` | string | `active` / `inactive`（列表默认只展示 `active`） |

- 至少预置 **2 个分类、每类 ≥ 2 个产品**（共 ≥ 4 条），便于 TOC 与列表验收
- 存储方式：内存、本地文件或数据库任选其一

### 2. 产品列表 API

- 提供 `GET /api/products`
- 支持查询参数（均可选）：
  - `category`：按分类过滤
  - `page`：页码，从 1 开始，默认 1
  - `pageSize`：每页条数，默认 10，最大 50
- 响应体示例结构：

```json
{
  "items": [ { "id", "name", "category", "price", "description", "status" } ],
  "total": 100,
  "page": 1,
  "pageSize": 10,
  "categories": ["分类A", "分类B"]
}
```

- `categories`：当前数据集中所有**有效产品**的去重分类列表（供 TOC 使用）
- 无匹配产品时返回空列表，`total: 0`，HTTP 200
- 非法参数（如 `page` < 1）返回 `400` 与明确错误信息

### 3. 单产品详情 API（可选但推荐）

- 提供 `GET /api/products/{id}`
- 存在且 `active`：返回 200 与产品对象
- 不存在或 `inactive`：返回 `404`

### 4. 产品列表页（Web UI）

- 提供可访问的**产品列表页**（path 在实现阶段确定，写入 `04-implementation.md`；示例 `/products`）
- 页面布局至少包含：
  - **TOC 区域**：展示所有分类（来自 API 的 `categories` 或等价数据）；点击 TOC 项应：
    - 滚动/定位到页面对应分类区块，**或**
    - 过滤列表仅显示该分类（两种方式任选其一，须在实现报告中说明）
  - **列表区域**：展示产品卡片/表格（名称、分类、价格、描述摘要）
- 支持**分页**或「加载更多」（与 API 分页一致）
- 空列表时展示友好空状态文案
- 加载中与错误状态有基本提示（不要求复杂动画）

### 5. TOC 行为约定

- TOC 条目与分类一一对应；分类名与 API `category` 字段一致
- 当前选中/激活的 TOC 项有视觉区分（高亮或 aria-current）
- 若仅 1 个分类，仍展示 TOC（或折叠为单条目，须在实现中说明）
- 键盘可访问：TOC 链接/按钮可被 Tab 聚焦（基本 a11y）

## 非功能需求

- **可配置**：服务端口、分页默认值等可通过环境变量或配置文件设置；**host/端口**由 workflow 配置 `workflow.e2e.base_url` 提供，**页面 path** 在实现报告中确认
- **可测试**：
  - API 测试：列表分页、分类过滤、空结果、非法参数、详情 404
  - **E2E**：浏览器打开列表页 → TOC 可见 → 点击 TOC 切换/跳转 → 列表展示预期产品（可用 Playwright MCP）
- **可运行**：README 或实现报告说明本地启动方式；启动后浏览器可访问列表页

## 验收标准

### API

1. `GET /api/products` 返回预置产品，`total` 与 `items` 长度正确
2. `category` 过滤后仅返回该分类产品
3. 分页参数生效（第二页数据与第一页不重复）
4. 响应含 `categories`，且与当前有效产品分类一致
5. `GET /api/products/{id}` 对有效 id 返回 200，无效 id 返回 404（若实现该接口）

### 列表页 / TOC / E2E

6. 浏览器打开列表页，可见 TOC 与产品列表
7. 点击 TOC 中某分类，列表或页面定位切换到对应分类内容
8. 列表展示字段与 API 数据一致（名称、价格等）
9. 分页或加载更多行为正确（若 UI 实现分页）
10. E2E 或自动化测试通过（含 API；浏览器场景可用 Playwright MCP）
