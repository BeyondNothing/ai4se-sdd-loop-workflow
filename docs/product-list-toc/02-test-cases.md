## 2. API / 集成测试用例明细

### 2.1 产品列表 `GET /api/products`

#### TC-API-01 — 默认列表返回预置 active 产品且分页元数据正确

| 项 | 内容 |
|----|------|
| **追溯** | 验收标准 1 |
| **优先级** | P0 |
| **前置条件** | 种子数据已加载；存在合计 ≥4 条 active 产品 |
| **步骤** | 1. 匿名请求 `GET /api/products`（不传查询参数，或仅依赖默认分页） |
| **预期结果** | 1. HTTP 200<br>2. `items` 均为 `status=active`，且不含 inactive<br>3. `total` 等于数据集中 active 产品总数<br>4. `page` 默认为 1，`pageSize` 默认为 10<br>5. 当页 `items` 长度 ≤ `pageSize`，且与 `total`/分页语义一致（`total` ≤ 默认 pageSize 时，`items.length == total`） |

#### TC-API-02 — 按 category 过滤仅返回该分类

| 项 | 内容 |
|----|------|
| **追溯** | 验收标准 2 |
| **优先级** | P0 |
| **前置条件** | 至少存在两个不同分类的 active 产品；记分类 A、B |
| **步骤** | 1. 请求 `GET /api/products?category=<分类A>` |
| **预期结果** | 1. HTTP 200<br>2. `items` 中每条产品的 `category` 均为分类 A<br>3. `total` 等于分类 A 下 active 产品数<br>4. 不含分类 B 的产品 |

#### TC-API-03 — 分页第二页与第一页数据不重复

| 项 | 内容 |
|----|------|
| **追溯** | 验收标准 3 |
| **优先级** | P0 |
| **前置条件** | active 产品总数 > 选定 `pageSize`（可用较小 `pageSize` 构造，如 `pageSize=2` 且 `total≥3`） |
| **步骤** | 1. 请求第 1 页：`page=1&pageSize=<N>`，记录 `items` 的 id 集合 S1<br>2. 请求第 2 页：`page=2&pageSize=<N>`，记录 id 集合 S2 |
| **预期结果** | 1. 两次均为 HTTP 200<br>2. 响应中 `page`/`pageSize` 与请求一致<br>3. S1 与 S2 无交集（依赖稳定排序；**不断言**具体排序键）<br>4. 两页 `items` 合集长度 ≤ `total`，且不超出该页容量 |

#### TC-API-04 — categories 反映全部有效分类且不随过滤收缩

| 项 | 内容 |
|----|------|
| **追溯** | 验收标准 4；澄清 Q8 |
| **优先级** | P0 |
| **前置条件** | 存在 ≥2 个 active 分类；记全量有效分类集合 C_all |
| **步骤** | 1. 请求未过滤列表，记录响应 `categories` 为 C0<br>2. 请求带 `category=<某一分类>` 的列表，记录 `categories` 为 C1 |
| **预期结果** | 1. 两次 HTTP 200<br>2. C0 与全部 active 产品去重分类一致（集合相等）<br>3. C1 与 C0 一致，**不因**当前 category 过滤而缩小<br>4. `categories` 不含仅出现在 inactive 产品上的分类（若该分类下无任何 active） |

#### TC-API-05 — 无匹配分类返回空列表且 HTTP 200

| 项 | 内容 |
|----|------|
| **追溯** | 验收标准 6 |
| **优先级** | P0 |
| **前置条件** | 服务正常；使用一个确定不存在于种子 active 数据中的 category 值 |
| **步骤** | 1. 请求 `GET /api/products?category=<不存在的分类>` |
| **预期结果** | 1. HTTP 200<br>2. `items` 为空数组<br>3. `total` 为 0<br>4. `categories` 仍为全部有效分类（不因空结果而消失） |

#### TC-API-06 — 页码超出可用范围返回空列表且 HTTP 200

| 项 | 内容 |
|----|------|
| **追溯** | 验收标准 6 |
| **优先级** | P0 |
| **前置条件** | 已知 `total` 与 `pageSize`，可计算超出末页的页码 |
| **步骤** | 1. 请求 `page` 远大于末页（如 `page=999&pageSize=10`） |
| **预期结果** | 1. HTTP 200<br>2. `items` 为空数组<br>3. `total` **仍为**当前过滤条件下匹配的 active 产品真实总数（不得因空页写成 0；与「不存在的 category → total:0」区分）<br>4. 响应中的 `page`/`pageSize` 与请求一致 |

#### TC-API-07 — 非法 page 参数返回 400

| 项 | 内容 |
|----|------|
| **追溯** | 验收标准 6 |
| **优先级** | P0 |
| **前置条件** | 服务正常 |
| **步骤** | 1. 分别请求 `page=0`、`page=-1`（及明显非正整数的非法页码，若协议允许字符串则再测非数字） |
| **预期结果** | 1. HTTP 400<br>2. 响应含明确可读的错误信息（指出分页参数非法） |

#### TC-API-08 — 非法 pageSize 参数返回 400

| 项 | 内容 |
|----|------|
| **追溯** | 验收标准 6 |
| **优先级** | P0 |
| **前置条件** | 服务正常 |
| **步骤** | 1. 请求 `pageSize=0` 或负数<br>2. 请求 `pageSize=51`（超过最大 50） |
| **预期结果** | 1. 上述请求均为 HTTP 400<br>2. 错误信息明确指出 pageSize 非法或超出上限 |

#### TC-API-09 — pageSize 边界合法值 1 与 50

| 项 | 内容 |
|----|------|
| **追溯** | 验收标准 1、6（边界） |
| **优先级** | P1 |
| **前置条件** | active 产品数足以观察截断（对 `pageSize=1` 至少 2 条） |
| **步骤** | 1. 请求 `pageSize=1`<br>2. 请求 `pageSize=50` |
| **预期结果** | 1. 均为 HTTP 200<br>2. 当页 `items.length` 分别 ≤1、≤50，且不超过 `total`<br>3. 响应 `pageSize` 与请求一致 |

#### TC-API-10 — 列表项字段完整性（用户可感知字段）

| 项 | 内容 |
|----|------|
| **追溯** | 验收标准 1、9（API 侧） |
| **优先级** | P0 |
| **前置条件** | 至少 1 条含完整字段的 active 产品（含可选 description 样本更佳） |
| **步骤** | 1. 请求默认列表<br>2. 检查任一条目字段 |
| **预期结果** | 1. 每条 item 至少包含：`id`、`name`、`category`、`price`、`status`；`description` 可缺省<br>2. `price` 语义为元；展示/序列化保留 2 位小数（或数值等价于两位小数精度）<br>3. 列表中产品 `status` 均为 `active` |

## 5. 与验收标准的追溯关系

| 验收标准 | 结论要点 | 对应用例 |
|----------|----------|----------|
| 1. 默认列表返回预置 active，`total` 与当页 `items` 正确 | API 默认列表 | TC-API-01、TC-API-10、TC-DOM-01 |
| 2. `category` 过滤仅返回该分类 | API 过滤 | TC-API-02 |
